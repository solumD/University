Тема: Продвинутые принципы проектирования REST API

Цель работы: закрепить и расширить навыки проектирования REST API: идемпотентность, безопасность, лимиты, пагинация, опциональные поля и внутренние API.

Задание:

Продолжение работы из Лабораторной №1
Использовать тот же репозиторий на GitVerse, что и для первой лабораторной работы.
Добавить новую функциональность и улучшения, не ломая уже реализованные возможности.
Безопасность и лимиты

Реализовать защиту API (например, аутентификацию или API-ключи).
Внедрить ограничение частоты запросов для всех конечных точек.
Отправлять заголовки X-Limit-Remaining и Retry-After.
Пагинация

Реализовать корректную пагинацию для конечных точек, возвращающих списки ресурсов.
Можно использовать страницы, смещения или курсоры, обосновать выбор в отчёте.
Опциональные поля

Реализовать возможность выбора полей, которые возвращает API (например, через параметр include).
Объяснить, какие поля сделаны опциональными и почему.
Внутренние API

Добавить хотя бы одну конечную точку для внутренних сервисов.
Обосновать в отчёте, почему она внутренняя, и какие упрощения или допущения в ней реализованы.
Документация

Обновить документацию OpenAPI (Swagger), включив все новые возможности.
Документация должна быть совместима с уже существующими версиями API.
Отчёт

Продолжение репозитория Лабораторной №1 на GitVerse.
В отчёте должны быть:

исходный код с новой функциональностью;
обновлённая документация API;
описание добавленных возможностей (идемпотентность, лимиты, пагинация, опциональные поля, внутренние API);
примеры запросов и ответов;
обоснование выбранных способов реализации.
Примечание: все новые изменения должны быть обратимо совместимыми с предыдущей версией API.
