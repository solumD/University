# Правила проекта

- Разделяй смысловые блоки внутри функций пустыми строками: подготовку данных,
  вызов с проверкой ошибки, следующий шаг и итоговый возврат. Вызов и проверка
  его ошибки остаются рядом.
- Сначала выполняй вызов функции или метода и присваивай результат переменным,
  затем возвращай эти переменные отдельным `return`. Не помещай вызовы внутрь
  возвращаемых выражений, включая создание ошибок и вложенные вызовы.
- Предпочитай последовательный код. Не оборачивай usecase в callback-функции
  ради выполнения обычных операций репозитория.
- Не добавляй явные транзакции и защиту от одновременных POST без отдельного
  запроса пользователя. Идемпотентность в этой лабораторной проверяется для
  последовательных повторов завершённого запроса.
- Автотесты не добавляй. Проверяй изменения сборкой, `make lint` и запросами
  к приложению по затронутым сценариям.
- Не добавляй в Git `config.local.json`, ключи доступа и файлы базы данных.
