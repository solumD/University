Проектирование и реализация REST API

Цель работы: Закрепить принципы проектирования REST API: простота, стабильность, версионность, идемпотентность, ограничение частоты запросов и документация.

Задание

Выбор предметной области
Каждый студент самостоятельно выбирает тему (например, библиотека, магазин, расписание, система задач и т. д.).
Определить необходимые сущности и связи между ними.
Проектирование API

Описать ресурсы и конечные точки.
Реализовать базовые CRUD-операции для выбранных сущностей.
Хороший API

Сделать структуру API простой и предсказуемой.
Использовать осмысленные имена конечных точек.
Задокументировать формат запросов и ответов.
API сложно менять

Добавить одно аддитивное изменение (например, новое поле или дополнительная возможность).
Объяснить, какие изменения считаются «ломающими» и почему их стоит избегать.
Версионность API

Реализовать несколько версий API (например, /api/v1/, /api/v2/).
Новые версии должны отличаться, при этом предыдущие продолжать работать.
Аутентификация

Выбрать способ аутентификации (например, API-ключ, JWT, OAuth).
Обосновать свой выбор в отчёте.
Идемпотентность

Добавить поддержку ключа идемпотентности для операций, связанных с созданием ресурсов (POST).
Повторные запросы с тем же ключом не должны создавать дубликаты.
Ограничение частоты запросов

Реализовать rate limiting для всех конечных точек API.
Отправлять в ответ заголовки X-Limit-Remaining и Retry-After.
Документация API

Оформить документацию в формате OpenAPI (Swagger).
Документация должна включать все версии API, конечные точки, схемы запросов и ответов.
Отчёт

Результаты работы оформить в виде репозитория на GitVerse.
В репозитории должны быть:

исходный код API;
инструкция по запуску;
документация (описание предметной области, конечные точки API, примеры запросов и ответов, выводы, обоснование выбора способа аутентификации).
в отчёте указать ссылку на GitVerse-репозиторий.
