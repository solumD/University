# Клиент библиотеки

Лабораторная работа № 3. Консольное приложение на Go с интерактивным меню для [Library API](https://gitverse.ru/bublik300/lab1). Клиент использует публичную версию `/api/v1`: ведёт каталог книг, авторов и читателей, оформляет выдачу и возврат. Локальная копия сервера находится в `API/`.

## Запуск

Нужны Go 1.26 или новее, Make, Python и [uv](https://docs.astral.sh/uv/). Для нового окружения подойдут Python 3.11 или 3.12.

При первом запуске из свежего клона скопируйте `main.py` и `requirements.txt` из каталога `lab12` репозитория автора в `Client_3/API/`. Эти команды из `Client_3` извлекают два файла проверенной версии сервера:

```sh
git clone --no-checkout https://gitverse.ru/bublik300/lab1.git API/source
git -C API/source archive 37eedf6774d1cea423d4c608536a49a87618c85a:lab12 main.py requirements.txt | tar -x -C API
```

Когда оба файла на месте, из каталога `Client_3` выполните в двух терминалах:

```sh
make api
```

```sh
make run
```

При первом запуске `make api` создаёт `.venv` и устанавливает зависимости автора из `API/requirements.txt`. Дальше сервер запускается из этого окружения. Swagger доступен по адресу <http://127.0.0.1:8000/docs>. Сервер хранит данные в памяти до остановки. В меню `?` показывает действия, `0` завершает клиент. Сервер останавливается через Ctrl+C.

Для другого порта используйте `make api API_PORT=8010` и `LIBRARY_API_URL=http://127.0.0.1:8010 make run`. Для сборки и проверки кода предусмотрены `make build` и `make lint`.

## Пример сеанса

| Действие в меню | Что ввести и проверить |
| --- | --- |
| **7 → 3** | Добавьте автора, затем создайте книгу с его ID. |
| **1 → 2 → 4** | Откройте список, найдите книгу по ID и измените её. При редактировании Enter оставляет значение поля. |
| **9 → 10** | Создайте своего читателя, запомните его ID и войдите с теми же данными. Пароль в терминале скрыт. |
| **11 → 12** | Укажите ID книги и читателя, затем повторите последнюю выдачу. Сравните ключ, ID и дату в ответах. |
| **13 → 14 → 5** | Посмотрите выдачу по ID, верните книгу и удалите её из каталога. |

Пункт **1** запрашивает размер страницы от 1 до 100, по умолчанию 10. Для нескольких страниц доступны `n`, `p` и Enter для возврата в меню. Клиент всегда передаёт `limit` и `offset`. Пример запроса и ответа после изменения года издания:

```http
GET /api/v1/books?limit=10&offset=0
```

```json
{"items":[{"id":1,"title":"Метель","year":1830,"author_id":1}],"total":1,"limit":10,"offset":0}
```

Вход выполняется через `POST /token` с полями формы `username` и `password`. Для операций выдачи клиент отправляет `Authorization: Bearer <токен>`. Ответ `POST /api/v1/borrow` с телом `{"book_id":1,"user_id":2}` содержит `id`, `status`, `borrow_date` и `return_date`. Один ключ `Idempotency-Key` соответствует одной попытке выдачи. Пункт **12** повторяет те же данные и ключ, в том числе после сетевого таймаута. Новая выдача заменяет предыдущую попытку. При выходе из программы или входе другого пользователя данные для повтора теряются.

Меню показывает остаток запросов из `X-Limit-Remaining`. При `429` клиент учитывает `Retry-After` и возобновляет отправку после указанной паузы по следующей команде. Для `401`, `404` и `422` он выводит причину ошибки. Таймаут одного запроса — 5 секунд.

## Структура

- `cmd/client` запускает приложение и читает `LIBRARY_API_URL`.
- `internal/menu` отвечает за ввод, навигацию по страницам и повтор последней выдачи.
- `pkg/library` содержит типы данных и HTTP-клиент на Resty.
- Локальная копия Word-отчёта для сдачи находится в `lab3/report.docx`.
